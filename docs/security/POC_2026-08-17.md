## PoC 3 — ALTO-03: delete_user exige reautenticação recente

Consulta somente leitura contra o catálogo remoto:

```sql
select
  p.oid::regprocedure as function_name,
  p.prosecdef as security_definer,
  pg_get_functiondef(p.oid) as definition
from pg_proc p
join pg_namespace n on n.oid = p.pronamespace
where n.nspname = 'public'
  and p.proname = 'delete_user';
```

Critério de sucesso: a definição contém `AUTH_STEP_UP_REQUIRED` e lê
`auth.jwt() -> 'amr'`, executando **antes** de qualquer `delete from`.

Prova estática de que o app mobile agora reautentica antes de chamar a RPC:

```powershell
rg -n "signInWithPassword|confirmarSenhaEApagarConta" "app/(tabs)/configuracoes.tsx"
```

Não chame `delete_user()` como teste — exclusão é irreversível. A inspeção
do catálogo é suficiente para comprovar a proteção.

Teste funcional recomendado, somente em conta de laboratório:

1. Autenticar normalmente (sessão com mais de 10 minutos).
2. Tentar excluir a conta sem reautenticar (ex.: chamando a RPC direto via
   um cliente REST com o token antigo) → deve falhar com
   `AUTH_STEP_UP_REQUIRED`.
3. Reautenticar com `signInWithPassword` e tentar novamente → deve suceder.

## PoC 4 — ALTO-04: parceiro não escreve saldo_atual direto

```sql
select tgname, tgenabled, pg_get_triggerdef(oid)
from pg_trigger
where tgrelid = 'public.caixinhas'::regclass
  and tgname = 'finflow_enforce_goal_balance_write';
```

Critério de sucesso: uma linha, `tgenabled = 'O'`, definição
`before update of saldo_atual`.

Teste funcional recomendado, somente em Supabase local com usuários
sintéticos A (dono) e B (parceiro) de um objetivo compartilhado fictício:

1. Como A, `UPDATE caixinhas SET saldo_atual = saldo_atual + 1 WHERE id = ...`
   → deve suceder (dono continua autorizado).
2. Como B, o mesmo `UPDATE` na mesma linha → deve falhar com
   `FINFLOW_DIRECT_GOAL_BALANCE_UPDATE_BLOCKED`.
3. Como B, chamar a RPC pública de movimentação (`move_goal`) sobre o mesmo
   objetivo compartilhado → deve suceder e o saldo refletir corretamente.

Não execute o passo 1/3 contra dados reais — use apenas fixtures
descartáveis em ambiente local.

## PoC 5 — Migrações fora de ordem (já corrigido)

```powershell
npx supabase db push --linked --dry-run
```

Antes da correção, este comando falhava com
`LegacyDbPushMissingRemoteError` porque `20260815000200` era anterior a uma
migração já aplicada (`20260816000100`). Depois de aplicar (com
`--include-all`), o comando deve retornar `upToDate: true` sem pedir a flag.

## PoC 6 — MÉDIO-02: webhook rejeita timestamp antigo

```powershell
rg -n "WEBHOOK_FRESHNESS_WINDOW_MS|parseEpochMillis" supabase/functions/_shared/mercado-pago.ts
```

Critério de sucesso: a assinatura é validada apenas se `ts` estiver a até 5
minutos do relógio do servidor, checado antes do HMAC. Teste unitário local
recomendado (segredo falso, sem tocar o endpoint publicado):

- assinatura válida, timestamp atual → aceita;
- assinatura válida, timestamp de 10 minutos atrás → rejeitada antes mesmo
  de computar o HMAC.
